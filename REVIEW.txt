REQUEST

A user asked for the multi-item queue display on the gameplay HUD,
"ideally at least 3 quickbuy slots." The maintainer requested separate 2-
and 3-item builds so users can choose 1, 2, or 3.

FINDING

The packaged script is the original mod's script, minus the removed row-cost
UMM toggle. It still fills preview slots 2-5 (QuickbuyUpcomingPreview2..5)
up to the saved Items shown value, which defaults to 3. The original
preview styles also remain. The 1-item build hides every preview with a
single appended rule:
  #QuickbuyUpcomingPreviewContainer { visibility: collapse; }

CHANGE

Only that rule and its comment are replaced:
  2 items: #QuickbuyUpcomingPreview3, 4, 5 { visibility: collapse; }
  3 items: #QuickbuyUpcomingPreview4, 5 { visibility: collapse; }
These ID selectors outrank the original .QuickbuyUpcomingPreviewSlot
.HasPreviewItem reveal rule. The tested #HudMiniContents .QueueSize
rule already relies on this precedence over a two-class rule.

Each file is therefore a maximum. The Items shown slider can still lower
the count, and the script hides all previews when it is 1. The default of
3 shows the full count for both variants. The 1-item build still ignores
the slider.

Preview icons, soul amounts, affordability border, positions
(margin-left 474px, 78px per slot), and shop/death/empty hiding come from
the original mod and are unchanged. Count label and corner badge over the
next item remain hidden in both variants.

  It evaluated the packaged stylesheet's visibility cascade by selector

  3-item, and original reference. Each used queue sizes 0-6; Items shown

LIMITATIONS

Mocked tests do not render Deadlock. Layout, overlap, and clipping are not
checked. By declared CSS values, the 1-item HUD spans about 390-464px
from the quickbuy panel's left edge. The 2-item version extends it to
about 544px, and the 3-item version to about 622px. This matches the
original mod's default, but has not been checked with the bytenode 4:3
HUD, whose item and ability bars are not in this package. Hidden slots are still updated by the script, matching the
original mod's 0.1-second refresh.

LIMITATIONS

Tests use mocked Panorama APIs and a limited CSS selector matcher. They
cannot establish rendering, font metrics, clipping, overlap, scroll behavior,
or live interaction with the companion HUD. The maintainer subsequently
reported in-game success for this compatibility build; the report does not
itemize every checklist step or resolution. This change does not promise
compatibility with every other HUD or every resolution.

Inherited pricing reads the game's ModCost label for owned-component
discounts; no second inventory discount is applied. Upgrade mappings use
English item names and can become stale. Sale estimates remain half the
displayed price, rounded down; full-refund windows are not modeled. The
integer parser does not handle abbreviated amounts such as 1.6k.

The Items shown setting remains exposed but extra previews stay hidden.
Total queue cost in shop controls the top Total Cost box. The obsolete
Souls needed in shop option remains removed; its legacy saved key cannot
change the top total or gameplay amount.

Preserved source maps cover original CSS, not appended rules. This limits
source-level diagnostics for additions. Development sources and test
harnesses are in this chat workspace, not the packaged Git repository.
