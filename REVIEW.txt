Enhanced QuickBuy — pre-install review
Reviewed 2026-10-20

Verdict
One packaging compatibility risk was found and corrected. No further
confirmed regression introduced by these changes was found in source,
binary, or simulated-behavior review. Native in-game rendering and owned
upgrade prices are not yet verified. The package is ready for an in-game
trial, not certified as fully tested in Deadlock.

Scope and method
Reviewed the conversation's final requirements, both supplied screenshots,
all five original VPK resources, the complete script and styles/layouts,
the original-to-modified changes, resource rebuilding, the final package,
and the limitations of the test harness.
Three independent reviews covered UI/layout, pricing/runtime behavior, and
compiled resources/archive structure.
The review also inspected publicly tracked native game resources for
current-soul formatting, the quickbuy price token, button dimensions,
base typography, and the soul icon.

Resolved finding: compiled-resource alignment
The first delivered package had correct lengths, offsets, CRCs, and MD5s,
but growing the stylesheet DATA block moved its SrMa source-map block
from offset 19376 to 21490. The latter is not aligned.
Source 2 Viewer's resource serializer aligns blocks to 16 bytes. Successful
decompilation alone did not establish the native game's acceptance of an
unaligned block. No actual game failure was observed.
The builder now inserts 14 zero padding bytes before SrMa and adjusts the
resource offsets and sizes. SrMa begins at 21504, a 16-byte boundary.
Padding is outside DATA, so the stylesheet and its content CRC are unchanged.
New assertions require preserved resource-block alignment.
The VPK was rebuilt and independently verified after this correction.

Final requested behavior
1. Remove fractions in shop item rows:
   The shop-only selectors collapse the added slash and cumulative label.
   Native ModCost and the normal soul icon are untouched.
   Buy and sell queue rows are covered. The gameplay HUD's existing styles
   and update behavior remain outside these shop-only selectors.

2. Top box becomes Souls Needed:
   The original panel, dimensions, icon frames, font rules, and placement
   are retained. Its heading changes to Souls Needed.
   Its value is the first pending buy entry's existing remainingSoulsCost.
   For the first item, this is max(0, native price - current souls -
   estimated sale proceeds). Sale proceeds are already included by the
   original calculator and are not subtracted again.

3. Show zero instead of disappearing:
   There is no affordability-based hiding branch for the top box.
   Empty queues produce zero. Empty-state CSS keeps the top box's full
   opacity and large icon rather than applying the original faded state.
   Explicit user settings can still disable the feature.

4. Move total to the lower-right footer:
   The new total is a child of QueueActions, which follows the scrolling
   buy and sell queues in the original layout.
   It is not a child of either scrolling list.
   The shop footer reserves at least 50px. The total is 150px wide, right
   aligned with a 2px inset inside the original panel's 15px edge padding.
   Clear Queue is capped at 180px within a 350px interior. Native base
   styles also apply an 80% scale to this Small button.
   These dimensions provide room in the source layout; real rendered
   geometry at the user's resolution still needs a game check.

5. Preserve the full-queue total:
   The footer receives exactly the value previously used in the top
   Total Cost box. Existing upgrade and sale-credit calculations are
   unchanged. Current held souls do not reduce this total.

6. Refresh and existing features:
   The original 0.1-second refresh remains.
   Each refresh reads current queue rows, prices, sales, and soul balance.
   The footer is created once and retried if its parent is initially absent.
   Repeated refreshes do not create duplicate panels.
   Gameplay HUD values, preview icons, classes, and preview-count controls
   match the original in the simulated comparisons.
   Native purchase, sale, clear, and reorder action handlers were not edited.

7. Settings:
   The former shop row-cost toggle is relabeled Souls needed in shop and
   controls the top box. The existing total toggle controls the footer.
   Saved toggle values are retained; default values are enabled.
   The global mod enable switch and gameplay HUD settings still apply.

8. Styling:
   The compact footer uses the existing translucent background/border
   colors, offWhite heading, shardColor value/icon, and sansMono number font.
   Native .goldIcon supplies the soul SVG, so the runtime-created Image
   does not require a separate SetImage call.

Limits and inherited assumptions
The tests run the complete scripts against a mock Panorama panel API.
Their CSS matcher checks selector precedence, not the native rendering
engine, custom-panel stylesheet scope, font metrics, or pixel placement.
The long-queue test confirms footer parentage and stable totals; it does
not render or scroll a real Deadlock menu.

Owned components: the mod reads the price supplied by Deadlock's ModCost
label. It does not independently inspect inventory. The test provides a
discounted native price and verifies the result/refresh; it does not prove
that the live game supplies that discounted price in every upgrade case.
This remains the main pricing behavior to check in game.

Number formatting: the original parser would misread abbreviated text
such as 1.6k. However, the native resources inspected use
{i:hud_cur_gold} and {i:mod_cost}, integer-format labels. There is no current
evidence that this inherited limitation affects the user's normal HUD.
The earlier unusual-input parity test only proves unchanged behavior;
it should not be read as proof of correct abbreviation support.

Recipes and sale estimates: the inherited upgrade table uses English item
names and fixed recipe mappings. It can become stale after game changes.
The sale estimate deliberately remains half of the displayed price, rounded
down, as requested; it does not predict full-refund windows.

Metadata: original RED2 editor/build provenance is retained. The preserved
SrMa source map still covers the original CSS prefix; appended rules have
no original source mapping. This limits source-level diagnostics for those
rules, and is not an observed rendering failure.

External HUD mods and native engine behavior have not been exercised.
