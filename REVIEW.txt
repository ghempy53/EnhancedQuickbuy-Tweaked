Both previous packages supplied panorama/styles/hud_quickbuy.vcss_c.
The companion's stylesheet imports its native base and applies two 4:3
position rules. It lacks Enhanced Quickbuy's added panel styles. If it
wins that shared path, the missing styles could explain the reported text
without working UI. This is a confirmed file conflict and a plausible cause
of the symptom; the friend's precise failure has not been reproduced.

This build gives Enhanced Quickbuy a private stylesheet path and points
its own compiled layout directly to it. It does not import the shared
quickbuy stylesheet, which could introduce unrelated native layout changes.
Two appended rules align the two-card shop summary and queue at a 17px left
margin under AspectRatio4x3. Other aspect ratios retain prior positioning.
The companion's other HUD and shop fixes remain independently packaged.
No companion resources are copied into this VPK.

PRESERVED BEHAVIOR

- Gameplay HUD: only the next queued item and its soul amount. Additional
  previews, count labels, and blue corner badge stay hidden. The next
  item's ready-to-buy border/glow and soul counter are retained.
- Queue rows: normal soul icon and item price; no slash/cumulative amount.
- Shop: top Total Cost box with the original full-queue calculation,
  including upgrades and estimated sale credits. Current held souls do
  not reduce that total. The empty queue shows zero when the box is enabled.
  No footer total or separate next-item amount appears in the shop.
- Gameplay amount:
  max(0, next purchase price - current souls - estimated queued-sale proceeds).
- Pricing, 0.1-second refresh, and native purchase, sale, removal, reorder,
  and clear handlers are unchanged from the tested main build.

LIMITATIONS

Tests use mocked Panorama APIs and a limited CSS selector matcher. They
cannot establish rendering, font metrics, clipping, overlap, scroll behavior,
or live interaction with the companion HUD. The maintainer subsequently
reported in-game success for this compatibility build; the report does not
itemize every checklist step or resolution. This change does not promise
compatibility with every other HUD or every resolution.

Inherited pricing reads the game's ModCost label for owned-component
discounts; no second inventory discount is applied. Upgrade mappings use
English item names and can become stale. Sale estimates remain half the
displayed price, rounded down; full-refund windows are not modeled. The
integer parser does not handle abbreviated amounts such as 1.6k.

The Items shown setting remains exposed but extra previews stay hidden.
Total queue cost in shop controls the top Total Cost box. The obsolete
Souls needed in shop option remains removed; its legacy saved key cannot
change the top total or gameplay amount.

Preserved source maps cover original CSS, not appended rules. This limits
source-level diagnostics for additions. Development sources and test
harnesses are in this chat workspace, not the packaged Git repository.
